# 常见错误、触发条件与排查

|现象/触发|易误判原因|排查与处理|失效边界|
|---|---|---|---|
|串口已登录，DONE 不亮|把 Linux 与 PL 启动混为一谈|先查服务是否负责加载 overlay，再核对 bit/hwh 与日志|不同板卡 LED 定义需查目标板资料|
|sudo 独立诊断报 No Devices Found|以为板子或 bitstream 坏了|比较正式服务的 PYNQ Python、用户、XRT/BOARD 环境；在匹配环境重试|环境变量值不能跨板照抄|
|LCD 只有白色背光|直接判定屏坏|检查显示服务是否启动、初始化是否执行，再排查线序、电源、复位和 SPI|ready 仅说明驱动执行，不证明实物显示|
|LED 接口迁移后标定或红灯失效|只改找书输出|统一定位、清屏、标定、异常提醒的输出通道，像素编号不变|相机/灯带位置改变需重标定|
|蓝衣显示黄色|直接改算法颜色阈值|比较原图与显示端，检查通道顺序及 RGB565|传感器本身偏色要独立查|
|拍照正确、预览是旧相机|只改了一个设备编号|检查两条采集路径并用稳定设备标识统一|USB 拓扑变化时重新确认|
|灯亮但通信断续、菜单冻结|多进程分别操作 GPIO 命令桥|单所有者、共享同一个锁，整帧写入及 flush 在锁内|不同 overlay 协议须重新设计互斥范围|
|有 GPU 却总耗时长|把采集/OCR 初始化计为纯推理|分段计时并核对每个实际 session 的 provider|仅 get_available_providers 不能证明运行在 GPU|
|保存了标定但仍不定位|把保存配置视作机位有效|检查新鲜帧、相机身份及光学锚点|不能放宽到使用历史帧强行点灯|
|电机接口存在但电机不动|以为菜单已启用运动|核对显式使能、看门狗和授权范围|本项目未做机械闭环验收，不能宣称可自动搬运|
