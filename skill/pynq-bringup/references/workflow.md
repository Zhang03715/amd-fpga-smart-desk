# 排障工作流与提示词

## 提示模板 A：分层定位

“请对目标 PYNQ 系统排障。现象为【现象】，现有服务为【服务名】，允许操作为【范围】。先列出系统层、PL 层、驱动层、外设层的证据与未知项；从只读检查开始，每次检查说明能排除什么。不要在未核对资源所有者时加载第二套 overlay。最后交付最小修复和可执行恢复命令。”

适用：串口可登录但外设无响应、LCD 白屏、服务状态矛盾。失效条件：板型、接口或当前所有者未知且无法读取；此时只给缺失信息和非侵入检查。

## 提示模板 B：从性能现象定位瓶颈

“分开测量采集、传输、预处理、推理、后处理、显示的时延。分别记录冷启动、稳定状态、分辨率和实际执行后端。根据测量决定是否降低刷新、复用模型、裁剪原图或迁移计算；不要把总时长归因于 GPU 推理。”

适用：画面刷新慢、OCR 总延迟高。失效条件：没有可追踪的时间戳或使用缓存结果；先增加测量再优化。

## 最小排查顺序

1. 串口/SSH 的新命令回应，确认进系统而非仅有旧启动日志。
2. 查看服务命令、运行用户、工作目录、环境变量与错误日志；记录当前状态。
3. 核对 bit/hwh 哈希、构建设备和应用约定的 IP 名称；项目有签名寄存器才读取，不能泛用其他项目地址。
4. 核对 GPIO 物理连接、独立供电与共地。接线变更应断电完成。
5. 沿原进程接口执行有限时间、低负载诊断；必须独立诊断时，记录停服务、测试、清理和恢复的全部结果。
6. 读取驱动状态并由观察者确认画面/灯光；若结果不符，回到上一层，不反复重载 FPGA 碰运气。
7. 正常重启后验证自动恢复；尚未做重启或长时间测试时明确保留此项。
